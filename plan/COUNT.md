# Count

A hop counts in a step when the accepting block's header time is inside that step. That header time is the file clock. The desk's notice time is not the file clock. Mini's local receive time is not the file clock.

1.14 over a 900-second step is **1,026 hops per family**. That product is exact. It is a score. It does not stop the step. A low minute can still leave the step above the line. The worst full minute is written beside the step. A minute that was not read in full stays marked. The gap is not filled. Hops after the window are listed apart.

The 32-family load is 2,700 seconds. 1.14 over that step is **3,078 hops per family**. The load reports the count and still runs the full 45 minutes. The counter then stays up through 13:55 UTC. Hops in that tail are late landings.

An accepted hop is a hop that landed in a block. Genesis is not a hop. A conflicting spend, already spent or orphan, is not a hop. Those are listed apart.

The desk proves each hash file, with git called by its full path, before the matching submit, and writes the On origin time after the push. A git error is logged as a git error. Empty output is a failed read. No proved file, no send.

Mini counts what lands. Mini does not invent a count. Mini's runner publishes the closed file under [counts/mini/](../counts/mini/README.md) at each count-off. The desk counts the same three windows and publishes the closed file under [counts/desk/](../counts/desk/README.md). Each machine writes only its own folder. The chat does not publish either folder.

The two readings stay separate. This plan does not average them. We do not claim either reading is the truth. The 8 Nov method is [the rehearsal count plan](https://github.com/STP-KAS/tn10-storm-2026-11-08/blob/main/plan/COUNT.md), on that night's clock.
