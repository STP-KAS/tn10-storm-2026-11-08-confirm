# What this plan copies

The pattern is [tn10-storm-2026-11-08 BENCHMARK.md](https://github.com/STP-KAS/tn10-storm-2026-11-08/blob/main/BENCHMARK.md). This plan keeps it, and it adds the three publishes that the 8 Nov runners did not do during the night.

- One repo. While the day is blank the name stays `tn10-storm-plan-confirm`. When the day is chosen the repo is renamed to `tn10-storm-YYYY-MM-DD` and both pastes get that day.
- Two root pastes. Each one is the whole story. The first sentence names the machine.
- The human boots the desk and Mini and leaves both logged in. Each machine reads its own file before 00:20 UTC on that day. That read starts one runner. A scheduled task is not the arm. There is no spoken word.
- One runner on the desk. One runner on Mini. A second runner is a fault.
- Git by its full path. Empty output is a failed read. Read once more, then stop.
- A hash file records Fixed, the local write, and On origin, the commit time of the rows. The runner writes On origin after the push, from origin. A file with no On origin line is not proof the push happened.
- The desk publishes `counts/desk/`. Mini publishes `counts/mini/`. Each machine writes only its own folder.
- A schedule may put two rows on the same clock only when a SKIP file turns one of them off before that clock opens.
- The steps, the offer 1.2, the line 1.14, and the abort line stay. A later run does not retune them to make the night look cleaner.

The pastes in this repo say DATE. A runner does not start while they say DATE.
